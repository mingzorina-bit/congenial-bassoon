# v0.0.6 AI Expression execution brief

Authority: Spec Freeze v0.1, CR-01–05 and `CODEX_IMPLEMENTATION_PLAN.md` v0.0.6. This is the next trial milestone after v0.0.5; stop at its boundary.

T1: Keep expression provider behind one async gateway. A request carries session ID, context revision, request ID, privacy revision, operation and only the active sentence and language direction. Debounce automatic sentence Shadow; cancel superseded work; validate the same identifiers and Privacy Gate before send and on receive. Mock tests cover late responses, another session, composition commit/cancel, Secure/Private transition, timeout, HTTP failure, malformed response and unavailable service. Errors leave local input intact and never enter candidate text.

T2: Show one sentence Shadow after a completed sentence when cloud assistance is enabled. Punctuation qualifies immediately after debounce; the frozen unpunctuated Chinese sentence fixture qualifies through a bounded length heuristic after the same debounce. Local word and gap help remains immediate and does not call the provider. Tab alone may request a Natural Expression, and only when its module is enabled; it may report that no better alternative is needed. Shadow and Natural have independent request lifetimes so closing details does not cancel the default sentence Shadow. A loading hint appears only after a perceptible delay. A privacy setting explicitly enables cloud assistance. No key is bundled or stored; no persistent sentence cache. Use a separate semantic evaluation record, not exact-string assertions for real AI.

Pre-flight interface: T1 produces `IExpressionProvider`, `ExpressionGateway` and request tickets; T2 consumes them on the WinUI thread. Privacy mode and editor/context revision invalidate both operations. The model never receives prior editor paragraphs, saved library, onboarding, repository documents, or a full chat history.

Approval gate: provider choice, HTTP/SDK library, current charges and data/cache terms require user approval. Until then, only provider-neutral gateway, Mock, UI behavior and local tests may be implemented. Real-provider completion and semantic PASS require both approval and an API key supplied locally outside chat.

Deferred user ideas remain deferred: Tab-to-close, Chinese Shadow pinyin, uncommitted mixed-pinyin segmentation, `youh` prediction and incomplete English hints.
