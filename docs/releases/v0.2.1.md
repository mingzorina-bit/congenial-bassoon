# v0.2.1 — broad lexicon interaction repair

User testing of v0.2.0 showed `beijing`, `shanghai`, `diannao` and `beijingdiqu` stayed as raw Latin input inside the editor, despite a real-Rime test that queried the engine directly. The session's bounded pinyin intent list rejected these inputs before reaching Rime. This repair queries the expanded offline engine for unknown Latin input when the current expression is Chinese, or when the expression is undecided and the Chinese profile is active. Clear English context and known English words still pass through; unknown or unavailable pinyin retains raw text.

The four reported examples gain independent, project-authored Shadow and detail rows (`own-curated-v021`), kept separate from the LGPL Luna/Essay pinyin sources and the earlier authored catalog. This is a bounded trial extension, not full bilingual coverage. No new external dependency, cloud call or TSF work is included.

Validation: context-routing regression, real Rime input-session integration with the exact four words and Shadows, Details catalog test, existing Core/Host suites, WinUI package and source audit. Windows CI and user retest **PENDING**; the v0.2.0 package is superseded for these examples.
