# Phase 1-A TSF Feasibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a separately installed, reversible x64 TSF trial that types through BilingualCore in two external desktop editors, without changing the WinUI prototype or automatically registering on the user's machine.

**Architecture:** A small COM in-process text service owns a serialized local Rime backend and adapts TSF key events/edit sessions to `InputSession`. It presents five visible candidates in a desktop-host popup; registration and unregistration are explicit scripts and separate from build/package. No cloud, learning, or surrounding-text collection occurs in the TSF DLL.

**Tech Stack:** C++20, Windows TSF/COM (`msctf.h`), existing RimeAdapter/BilingualCore, CMake, PowerShell, Windows CI.

**Spec:** `docs/tsf/PHASE1A_DESIGN.md` (user approved 2026-10-12).

## Global Constraints

- Keep the existing Space=Primary, Enter=raw, arrows=highlight, Esc=cancel meanings.
- Do not intercept Tab or advertise Shift+Enter in external editors in this spike.
- Use the already approved, pinned Luna/Essay sources; add no new package or data dependency.
- No registration or activation during CI, packaging, or installation on the user's machine without the separate registration/signing review.
- No network, OpenAI, SQLite learning, background process, or global hook in `BilingualTsf.dll`.
- Treat a missing Rime engine, failed edit session, disabled keyboard, or lost focus as a no-crash, no-stale-insertion condition.

## Review Focus

- An English word in an English expression must pass through; test `computer` and unknown Latin text without forced Chinese conversion.
- An incomplete composition cancelled with Esc or focus change must leave no stale candidate popup or delayed insertion.
- A failed or denied TSF edit session must preserve host input rather than swallow a key.
- A missing data directory must disable TSF conversion without crashing the editor.
- A password/disabled field must never display candidates or retain text; record a human negative test because host behavior varies.

### Task 1: Isolated TSF key state adapter

**Files:** Create `src/TsfHost/TsfKeyRouter.h/.cpp`; create `tests/TsfHostTests/TsfKeyRouterTests.cpp`; modify `CMakeLists.txt`.

**Interfaces:** `TsfKeyRouter` consumes `InputSession&`, `KeyEvent { virtualKey, character, shift, ctrl, alt }`, and a focus/sensitivity flag. It produces `KeyResult { handled, raw, candidates, highlighted, commit, cancelled }` by calling existing Core methods; it never writes into a Windows document. `reset()` clears active composition and pending state on focus loss.

- [ ] Write failing native tests for `nihao`/`beijing` candidates; Space Chinese commit; Enter raw commit; arrows/highlight; Esc cancellation; `computer`/unknown English passthrough; disabled/secure context; focus reset.
- [ ] Run `ctest --test-dir build -C Release --output-on-failure` and confirm the new test fails before implementation.
- [ ] Implement only key routing and state snapshots in `TsfKeyRouter`; preserve exact Core semantics and never intercept Tab/Ctrl/Alt combinations.
- [ ] Run the new test and existing Core/Context/Rime tests to green.
- [ ] Review the adapter diff for any copied candidate ranking or Shadow logic; none may exist outside Core.

### Task 2: COM/TSF activation and document edits

**Files:** Create `src/TsfHost/TsfService.h/.cpp`, `src/TsfHost/TsfModule.cpp`, `src/TsfHost/TsfComposition.h/.cpp`; modify `CMakeLists.txt`; extend `tests/TsfHostTests` with a mock edit-command boundary.

**Interfaces:** `TsfService` implements `ITfTextInputProcessorEx`, `ITfKeyEventSink`, and `ITfThreadMgrEventSink`. `TsfComposition` receives a `TsfEditCommand { replaceComposition, commit, cancel }` and performs it only inside `ITfContext::RequestEditSession`; TSF COM references are released on deactivation/focus loss. Fixed CLSID and profile GUID constants live in one header and are reused by registration scripts.

- [ ] Write failing adapter/edit-command tests for no stale commit after focus change, denied edit session, and no swallowed keys when TSF is disabled.
- [ ] Implement COM exports/class factory and TSF activation/deactivation with balanced reference counts, advising and unadvising sinks.
- [ ] Implement selection/range composition start, update, commit and cancel inside edit sessions. Apply commit text exactly once; if an edit is denied, leave the host key unhandled.
- [ ] Build x64 `BilingualTsf.dll` in CI; run adapter/Core tests and inspect compiler warnings and exported COM functions.
- [ ] Record all host-state assumptions that still need human validation in the release note.

### Task 3: Candidate presentation and fail-closed lifecycle

**Files:** Create `src/TsfHost/TsfCandidateWindow.h/.cpp`; modify `TsfService.cpp`; extend native adapter tests.

**Interfaces:** `TsfCandidateWindow` consumes a snapshot of at most five Core candidates and highlighted index plus a caret rectangle, and exposes `show/update/hide`; it never owns document state or changes candidate ordering. The service hides it on commit, cancel, disabled/sensitive context, focus loss and deactivation.

- [ ] Test snapshot truncation and highlight consistency at five candidates; test popup hide on every terminal state.
- [ ] Implement a non-activating desktop popup anchored to TSF's text extent, with a host-visibility check and a no-UI fallback.
- [ ] Confirm via native tests and CI that no UI call is made from a delayed callback after the TSF context changes.
- [ ] Keep app-container/UI-less host compatibility explicitly unclaimed until the appropriate TSF UIElement work and host tests exist.

### Task 4: Reversible trial package and review gate

**Files:** Create `scripts/Package-TsfSpike.ps1`, `scripts/Register-TsfTrial.ps1`, `scripts/Unregister-TsfTrial.ps1`, `docs/tsf/PHASE1A_TRIAL.md`; modify `.github/workflows/windows.yml`, `scripts/Audit-Sources.ps1`, `PROJECT_PROGRESS.md`.

Registration script has a default dry-run/report mode and requires an explicit switch to perform changes; unregister targets only the fixed trial CLSID/profile and records outcomes.

- [ ] Review registration scope, signing requirements, privilege level and rollback behavior with a concrete package before installing on the user's computer. If any is unknown, keep install disabled.
- [ ] After that gate, human trial in Notepad and one other named desktop editor: type `nihao` and `beijing`, navigate/highlight, Space/Enter/Esc, switch focus, disable/unregister and restore the normal keyboard. Record secure field separately and keep Phase 1-A incomplete if it leaks candidates or text.
